3.1 Frontend

Responsibilities

• User Interface
• Authentication
• Upload Management
• Dashboard Rendering
• Search Filtering
• Document Viewing

Hosting

Delivery

-------------------------------------------------------------------------------

3.2 Authentication

Amazon Cognito manages

• User Registration

• Login

• JWT Token Generation

• User Identity

The backend trusts only validated JWT tokens.

-------------------------------------------------------------------------------

3.3 API Gateway

API Gateway acts as the entry point for all backend requests.

Responsibilities

• Request Routing

• JWT Authorization

• HTTPS Termination

• CORS

-------------------------------------------------------------------------------

3.4 Lambda Functions

KnowledgeHub consists of three logical Lambda groups.

User APIs

Handles

• Document APIs

• Sharing APIs

• Dashboard APIs

• Administration APIs

------------------------------------------------

Ingestion Lambda

Handles

• Upload Validation

• Version Assignment

• Object Movement

• Metadata Creation

• Audit Creation

• Statistics Updates

------------------------------------------------

AI Processing Lambda

Handles

• Text Extraction

• Summary Generation

• Keyword Extraction

• Metadata Updates

• Processing Completion

4. DATABASE ARCHITECTURE
===============================================================================

KnowledgeHub uses a Single Table Design.

Each document acts as the aggregate root.

Example

DOC#123

│

├── DOCUMENT

├── VERSION#000001

├── VERSION#000002

├── VERSION#000003

├── SHARE#USER123

├── SHARE#USER456

├── AUDIT#20260703T091200Z

├── AUDIT#20260703T113500Z

-------------------------------------------------------------------------------

Global Secondary Indexes

GSI 1

Owner Documents

------------------------------------------------

GSI 2

Shared Documents

------------------------------------------------

GSI 3

Administrator Documents

------------------------------------------------

GSI 4

Processing Documents

9. CONCURRENT VERSION CREATION
===============================================================================

Two users upload simultaneously.

               Upload A

                    |

             Read Latest Version

                    |

             Conditional Update

                    |

              Version 7 Created

------------------------------------------------

               Upload B

                    |

             Read Latest Version

                    |

        Conditional Update Fails

                    |

                 Retry

                    |

             Read Latest Version

                    |

             Version 8 Created

Optimistic concurrency guarantees sequential version numbers without locking.

===============================================================================
16. DESIGN PRINCIPLES
===============================================================================

KnowledgeHub follows the following architectural principles.

• Serverless First

• Event-Driven Architecture

• Single Table DynamoDB Design

• Immutable Version History

• Direct Browser-to-S3 Uploads

• Asynchronous AI Processing

• Infrastructure as Code

• Least Privilege Security

• Separation of Concerns

• Horizontal Scalability
