1. PURPOSE
===============================================================================

This document defines the backend design of KnowledgeHub.

It specifies

• Access Patterns
• DynamoDB Single Table Design
• Entity Models
• Index Design
• REST API Specification
• Transaction Design

The objective is to design the database around application access patterns
instead of relational entities.

===============================================================================
2. DATABASE PHILOSOPHY
===============================================================================

KnowledgeHub uses a Single Table Design in Amazon DynamoDB.

The design follows an aggregate-root approach.

Each document acts as the aggregate root.

All data related to a document is stored within the same partition.

This minimizes cross-partition queries and allows complete document retrieval
using a single partition query.

10. CONCURRENCY CONTROL
===============================================================================

The upload API never assigns version numbers.

Version numbers are assigned only by the Ingestion Lambda.

The Ingestion Lambda uses optimistic concurrency through DynamoDB
conditional updates when assigning version numbers.

Version numbers are allocated only after the uploaded object has been
validated.

This guarantees sequential version numbers even during concurrent uploads.
Concurrent uploads shall automatically receive unique sequential version
numbers.

===============================================================================
12. FAILURE HANDLING
===============================================================================

If upload validation fails

↓

Temporary upload deleted.

-------------------------------------------------------------------------------

If AI processing fails

↓

Document remains.

↓

Status becomes FAILED.

-------------------------------------------------------------------------------

If metadata creation fails

↓

Temporary upload deleted.

↓

Operation retried.

===============================================================================
ATOMIC OPERATIONS
===============================================================================

The following operations shall be executed atomically.

• Version number assignment

• Document metadata creation

• Version metadata creation

If any operation fails before completion, no partial metadata shall remain.

Document metadata shall only become visible after successful completion of the
ingestion stage.
